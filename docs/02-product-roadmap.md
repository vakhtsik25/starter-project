# 02 — Product Roadmap

> Goal: turn the idea into a sequence of things to build/test, ordered so we learn the most, fastest, for the least effort.

Do this AFTER [01-business-idea.md](01-business-idea.md) is committed. Rule of thumb: the roadmap's first job is to test the **riskiest assumption**, not to build the prettiest product.

## Now → Next → Later

We plan in three buckets, not exact dates. Move cards left as they get done.

### 🔨 NOW (this month — the riskiest thing first)
The smallest thing that tests whether people actually want this.

| What | Why it matters | Owner | Status |
|------|----------------|-------|--------|
| e.g. Talk to 15 target customers | Confirm the problem is real | A | ☐ |
| e.g. Fake "landing page" + signup button | See if anyone clicks/pays | B | ☐ |
| | | | |

### ⏭️ NEXT (once NOW proves the idea has legs)
| What | Why it matters | Owner | Status |
|------|----------------|-------|--------|
| e.g. Build the simplest usable version (MVP) | Give real users something to try | | ☐ |
| | | | |

| | |

## Milestones (what "done" looks like at each stage)
- [ ] **Problem validated** — X customers confirmed the pain in their own words
- [ ] **Demand signal** — Y people signed up / pre-paid / joined waitlist
- [ ] **MVP live** — first real user completes the core task
- [ ] **First paying customer**
- [ ] **10 paying customers**
